## Verified fixes, in implementation order

1. **Backup medal integrity:** baseline inspection accepted a collected medal linked to another medal's event and duplicate collected keys. Validation now checks both album and medal identity against the referenced event and rejects duplicates before replacement. Targeted tests include missing events and valid archives. No schema or format change, and no personal archive was edited.
2. **Route crash and CPU work:** the original recursive simplifier threw `RangeError: Maximum call stack size exceeded` on 5,000- and 12,000-point alternating routes. The recovery preview feeds complete walks into this function before its final sample limit. An explicit work stack eliminates recursion depth; shared per-range projection/baseline calculations remove repeated trigonometry. A short date-line fixture also exposed an unwrapped longitude subtraction; the corrected projection removes an 11.132 m deviation at 15 m tolerance and preserves it at 10 m. Endpoint objects and ordering remain intact; stored routes are unchanged.
3. **Completion stale state and polling:** a delayed district query published after the city query and replaced its list, reproduced by executing the actual component callback. Requests now check generation, current scope and visibility; cleanup and clear invalidate pending results. A pending summary read prevents additional timer-driven reads, retries after failure and cannot publish after cleanup. Delayed statistics/automatic-refresh-state reads also respect cleanup.

Each batch passed targeted checks and typecheck before the next batch. New tests are included in the existing geometry, completion and backup groups.

## Measurements

Node 24.15.0 on the same Windows desktop, old/new implementations in the same process. Route workloads use 1.5 m tolerance, one warm-up and five measured runs; numbers are medians. A separate 300-case comparison across ordinary random routes and three tolerances retained identical point objects/order.

| Route workload | Before | After | Retained points |
| --- | ---: | ---: | ---: |
| Smooth 10,000 points | 9.00 ms | 3.11 ms | 96 in both |
| Alternating 1,000 points | 25.01 ms | 8.91 ms | 982 in both |
| Alternating 5,000 points | Stack overflow | 215.69 ms | 4,982 after |
| Alternating 12,000 points | Stack overflow | 1,265.20 ms | 11,982 after |

Reproduce with `node scripts/benchmark-route-simplification.js 941cc1c6eeae1284e7cc9de3aa27d3fec4d86b58`. Timings vary by machine/JIT/load; these are not native frame-time measurements. The longer alternating fixture remains quadratic and can visibly block; no unsupported claim of smooth long-route performance is made.

Polygon baseline (`npm run measure:polygons`, five-run medians): 5,000-cell corridor partition 2.4 ms / contours 9.6 ms; solid 50,000-cell grid 13.9 / 24.6 ms; 3,025 islands 0.7 / 16.4 ms. Polygon generation was not changed, so no before/after polygon speedup is claimed. One-cell growth retained its polygon key.

For completion polling, a deterministic stalled-query fixture runs the initial load and three timer ticks. The old implementation starts four queries; the new implementation starts one. This measures work admission, not database latency or a native frame-rate gain.
